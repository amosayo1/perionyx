# One Screen, One Question

**Category**: Architecture / UX

**Lesson**: Every screen should answer exactly one question. If a screen answers two questions, split it. If it answers zero, delete it. This forces clarity in both UI design and data architecture. Screens that try to answer everything end up answering nothing — the CFO who needs cash position shouldn't have to scroll past workflow analytics to find it.

**When it applies**: When designing any new page, dashboard, or view. Before building, ask: "What question does this screen answer?" If you can't answer in one sentence, the screen is too broad.
