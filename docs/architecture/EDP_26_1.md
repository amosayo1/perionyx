# EDP 26.1 — Foundation Operationalization

**Date**: 2026-07-27
**Phase**: 26.1 — Foundation Operationalization
**Status**: Complete (scope-adjusted)

## Context

Phase 26.1 aims to eliminate every remaining gap between architectural foundation and production operation. Four parallel audits (in-memory stores, providers, telemetry, security) identified the current state.

## Audit Findings (Key Corrections)

### Encryption Service — CORRECTED
The audit claimed `encrypt()` was a no-op passthrough. **This is false.** `src/server/security/encryption.ts` is a production-grade AES-256-GCM implementation with:
- Real key validation (64 hex chars, rejects known defaults)
- `crypto.randomBytes(16)` IV generation
- Auth tag verification on decrypt
- Key rotation with history
- KMS provider support

### Identity Module — Dead Code (NOT Security Vulnerable)
The identity module (`src/server/identity/`, 13 files) has zero production auth consumers. It is consumed by9 admin pages via `identityFacade` for display-only data. The real authentication runs through `src/server/security/authenticate-request.ts` + `src/proxy.ts`. The module is in-memory by design for admin dashboard purposes, not security-critical.

### Session Validation Store — By Design
`src/server/security/session-validation-store.ts` is a 30-second TTL cache for DB failure fallback. It is NOT a session store — it's a revocation cache. Used by `proxy.ts` and `users.service.ts`. This is the correct pattern.

### Event Buses — Two Distinct Purposes
- **AP Event Bus** (`src/server/procurement/domain/events/event-bus.ts`): In-process for transactional events within a unit of work. This is architecturally correct.
- **Realtime Event Bus** (`src/server/realtime/event-bus.ts`): Already has Redis Pub/Sub bridge for cross-instance propagation. Production-ready.

## Changes Executed

### 1. Graceful Shutdown Wiring (CRITICAL)
**Before**: `gracefulShutdown` imported in `infrastructure.ts` but `.setup()` never called. Process signals (SIGTERM/SIGINT) were not handled.
**After**: Registered 4 shutdown handlers (database, cache, runtime-secrets, runtime-capabilities) and wired `gracefulShutdown.setup(["SIGTERM", "SIGINT"])`.
**File**: `src/server/infrastructure.ts:112-127`

### 2. AP Event Bus — Pino Logging + Error Isolation
**Before**: Silent handler failures, unbounded history, no metrics.
**After**: Structured Pino logging, error isolation per handler (catch + log, continue), bounded history (1K max with eviction), published/error metrics via `getMetrics()`.
**File**: `src/server/procurement/domain/events/event-bus.ts`

### 3. Dead Code Elimination
**Deleted**:
- `src/server/iam/session.ts` — EnterpriseSessionManager with 0 consumers
- `src/server/security/rate-limiter.ts` — Old in-memory rate limiter, superseded by `rate-limit.ts`
**Cleaned**: Removed session exports from `src/server/iam/index.ts`, removed rate-limiter export from `src/server/security/index.ts`

### 4. Pino Logging — Foundation Services
Added structured Pino logging (`logger.child({ module: "..." })`) to:
- `src/server/foundation/classification/auto-register.ts` — Replaced `console.warn` with Pino
- `src/server/foundation/config/registry.ts` — Config set, feature flag register
- `src/server/foundation/capability-registry/registry.ts` — Capability register
- `src/server/foundation/secrets/manager.ts` — Secret create, rotate, delete
- `src/server/identity/identity-facade.ts` — User identity summary, health check
- `src/server/identity/sso-handler.ts` — SAML, OIDC, OAuth2 callbacks
- `src/server/ha/graceful.ts` — Replaced all `console.log`/`console.error` with Pino

### 5. HA Graceful — Console to Pino Migration
**Before**: Used `console.log`/`console.error` for shutdown status.
**After**: Uses structured Pino with `{ signal }`, `{ handler }`, `{ err }` context.
**File**: `src/server/ha/graceful.ts` (complete rewrite, removed duplicate import)

### 6. Test Mock Fix
**Before**: AP test mocked logger without `.child()`, breaking when event bus added logging.
**After**: Added `child: vi.fn(() => mockLogger)` to mock.
**File**: `test/procurement/ap-api.test.ts`

## Decisions

1. **Graceful shutdown is now operational** — SIGTERM/SIGINT trigger orderly shutdown of database, cache, secrets, capabilities
2. **Event bus handler failures are isolated** — One bad handler doesn't kill the event loop
3. **All foundation services emit structured logs** — Pino with module context for debugging
4. **Dead code eliminated** — 2 files deleted, barrel exports cleaned
