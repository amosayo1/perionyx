## Key Decisions

### Decision 1: Resolve All 6 Conditions (not selective)

**Rationale**: All 6 conditions were real findings with evidence. Selective resolution would leave known risks unaddressed. The 3-4 week timeline from Phase 26.2 was achievable for all 6.

**Alternatives Considered**:
- Resolve only Critical (C-01, C-02): Rejected — 4 High/Medium conditions remain
- Resolve Critical + High (C-01-C-05): Rejected — C-06 is simple and low-risk
- Defer to Phase 26.4: Rejected — delays certification unnecessarily

### Decision 2: Preventive Controls (not just fixes)

**Rationale**: Fixing conditions without prevention guarantees recurrence. Every condition needed both a code fix AND a preventive control (ESLint rule, CI check, or pattern enforcement).

**Alternatives Considered**:
- Fix-only approach: Rejected — conditions will return in new code
- Code review only: Rejected — humans forget; automation doesn't
- Test-only: Rejected — tests verify current state, not future code

### Decision 3: BoundedRingBuffer (not capacity-aware arrays)

**Rationale**: A standalone utility class is simpler to understand, test, and reuse than adding capacity logic to each array. The class is 55 lines with clear semantics.

**Alternatives Considered**:
- `Array<T>` with manual eviction: Rejected — error-prone, not reusable
- `Map` with size limit: Rejected — different semantics (keyed vs. sequential)
- Third-party library: Rejected — adds dependency for 55 lines of code
- Capacitated array mixin: Rejected — more complex than needed

### Decision 4: ESLint `no-empty-catch` (not warning)

**Rationale**: Empty catches are always bugs in foundation code. Warning severity allows them to accumulate. Error severity blocks merges — the only way to prevent regression.

**Alternatives Considered**:
- Warning severity: Rejected — warnings are ignored in CI
- No ESLint rule: Rejected — no automation means recurrence
- Custom ESLint plugin: Rejected — overkill for one rule

**Title**: Preventive engineering is cheaper than corrective engineering

**Statement**: "Every certification condition resolved without a preventive control is a condition that will return. One ESLint rule prevents thousands of future bugs.
